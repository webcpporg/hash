= hash: hashing and key derivation for {cpp}
:toc: left
:toclevels: 2
:idprefix:
:sectanchors:
:example-caption!:
:attribute-missing: warn

hash is one entry point for hashing and key derivation in a {cpp}20 program,
on every target webcpp has, one of the libraries of
https://github.com/webcpporg/webcpp[webcpp]. The algorithms are Boost.Hash2's
and those of C libraries, each a backend that the program names in its own
Jamfile.

This page is written for two readers at once: a developer who knows little
cryptography and wants the right function for an application, and a language
model that reads it to choose a function for someone. Both can start at
<<hash-choose>>, which goes from a need to a function, a backend and a
program that shows it. The chapters after it teach one family of functions
each, opening with two tables that compare everything in the family, what
each function is and how to choose it; each section says what a function is
for, shows a program of `example/` that the build compiles and runs on every
target with the output it prints, and lists the mistakes that cost security.
Three chapters then follow an application from end to end: a peer-to-peer
network, a cryptocurrency wallet, and the privacy of a login and a password
manager. The <<reference,reference>> that closes the page lists every name
the headers declare, and
link:llms.txt[llms.txt], beside this page, is the same guide as an index for
language models (<<hash-llms>>).

[#hash-llms]
== An index for language models

link:llms.txt[llms.txt], published beside this page, lists every function of
hash with its header, its standard, what it is for, its status, when to choose
it and the backends that implement it, each with the Jamfile line and the
targets, then every row of <<hash-choose>>, in the
https://llmstxt.org/[llms.txt] form: a model that reads it can answer "which
function, which backend, which Jamfile line" without reading the page. It is
generated with the tables of this page from the same data,
`doc/capabilities.json` and `doc/guide.json`, by `tools/hash/doc_tables.py`,
whose check runs when the page is built; the two never disagree.

[#reference]
== Reference

Every name hash declares, in the namespaces `webcpp::hash` and its `backends`
and `kdfs`, from the Doc Comments of its headers: each class, function, type
and enumerator with its declaration, what it does, what it asks of its caller
and how it fails. The other sections teach the library; this one is where a
name is looked up.
